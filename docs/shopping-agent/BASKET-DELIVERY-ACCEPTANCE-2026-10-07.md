# 混合商品与配送实现验收

日期：2026-10-07。用户授权在当前独立维护的 A/B 项目中实现这两项功能。
结论：**实现完成，当前工程门禁、真实模型及浏览器验收通过。** 本轮未提交、推送或部署；验收运行在独立目录和随机端口，不重启现有演示实例。

## 功能范围

- 同商家最多 10 行需求、整单 1–20 杯，逐行搜索和选择，重复商品合并数量。
- 整单报价展示每行单价、数量、行小计、所有费用和最终预算校验。
- 表单选择自取或配送；配送需有效收件人、电话及详细地址，不交给模型生成。
- demo 拿铁和美式支持配送，整单配送费为各所选商品配送费的最大值，一次收取。
- 整单原子库存预留、一次授权及模拟支付、一笔订单；任一项失败不部分成交。
- 修改配送信息或商品须重新报价与确认；结果未知查询原尝试，重启不重复购买。
- 共同应用契约 0.2.0，SQLite schema 3；保留旧单商品自取请求、报价 hash 与历史数据。

仍为本地模拟支付和履约，不对接真实物流、支付、配送区域覆盖或生产账户。

## 使用与边界

手动模式勾选“一次购买不同商品”，填写各行关键词和杯数，在每组候选中选商品，再点击“查看整单最终报价”。Agent 模式可输入“一杯拿铁和一杯美式”，总杯数填2、总预算填40；选择配送并填写表单。核对39.90元的最终报价后，点击确认模拟购买。

可用 `bun tests/shopping-e2e/browser-http-server.ts --basket-check` 运行新增页面验收；`bun run shopping:browser` 继续运行原恢复验收。真实模型需要本地自己的密钥，不作为无密钥 CI 的前置条件。

本轮扩展的是应用层购物契约与 A/B 实现，未修改 OCP 标准。仍限同一商家，单笔最多10行、合计20杯；demo 仅拿铁与美式声明支持配送，手冲礼盒等仅支持自取。配送信息保存于本地授权条款和模拟订单，用于验证完整履约资料及不可篡改绑定；没有真实骑手调度、物流轨迹、配送区域承诺、支付或生产账户系统。
